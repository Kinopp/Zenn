## 適用
**開始時期：** プロジェクトが本格的に開始となってから
**対象：** 顧客に対する成果物や検討資料または、それに準ずるもの


## 進捗率の定義
昨年度も同じような定義を作成し、進捗を管理しましたが、昨年度の反省を踏まえ、下記の通り定義しました。
※　上原さんとは認識合わせ済みです。

* WBS対象：WBSの項目として定義するもの
   * 「◎」：必須
   * 「〇」：資料や作業者を考慮し、実施する・しないを決める


| 進捗率 | ステータス                     | 説明                                                                                                                       | WBS対象 | 
| ------ | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------- | :-----: |

### ＜昨年度との主な変更点＞
#### ① やり直しをなくすために下記のタスクを明記
* 意識合わせ完了：
* 目次・枠組み作成とレビュー完了：
* 中間レビュー完了

#### ② 関連する成果物の修正漏れをなくすために下記のタスクを明記
* 影響調査の実施完了
※ 本来、WBS作成時に関連資料の修正タスクを考慮しているはずであるが、レビューが終わり、修正が確定したタイミングで、改めて漏れがないかを確認する。明らかに関連がない成果物でも、「指さし確認」の意味合いでも簡単に行う。


## 評価指標
下記３点について評価を行います。

### 1. 最終レビューでの指摘数・大幅修正率
* 【説明】
    * 90%（最終レビュー）段階で、構成の組み直しや目的の乖離といった「致命的な手戻り」が発生した割合。

* 【狙い】
    * 10%（意識合わせ）や60%（中間レビュー）のレビューなどが形骸化していないかを検証。

* 【測定方法】
  * 差し戻しの定義：「認識のズレ」といえるレベルのやり直し。誤字脱字や、表などの表現方法の修正は含めない。
  *  作業者より申告。朝会で確認。Notesに記録

| 項目     | 内容                                   | 
| -------- | -------------------------------------- | 
| 評価周期 | 週次                                   | 
| 評価指標 | 必要な作業ステップ漏れ率               | 
| 目標     | 必要な作業ステップに漏れがない         | 
| 達成度   | 必要な作業ステップ漏れ率5％以内        | 
| 評価方法 | 必要な作業ステップ漏れ／全ステップ件数 |  

### 2. テンプレート項目スキップ率
* 【説明】
    * 必要であったが、WBS作成時に「不要」として削除されたステップの割合。

* 【狙い】
    * 必要な工程まで削りすぎて、後の品質に影響していないかを確認。

* 【測定方法】
  * 「1.致命的な手戻り」が発生したタスクの中で、必要だったにもかかわらず、テンプレート項目をスキップしたと判断できる作業の件数をカウント。
  *  作業者より申告。朝会で確認。Notesに記録

| 項目     | 内容                                   | 
| -------- | -------------------------------------- | 
| 評価周期 | 週次                                   | 
| 評価指標 | 必要な作業ステップ漏れ率               | 
| 目標     | 必要な作業ステップに漏れがない         | 
| 達成度   | 必要な作業ステップ漏れ率5％以内        | 
| 評価方法 | 必要な作業ステップ漏れ／全ステップ件数 |  

### 3. 後続タスクでの「突発的な仕様変更・修正」発生数
* 【説明】
    * あるタスクが100%完了した後に、後戻りが発生した関連タスクの数。

* 【狙い】
    * 「影響調査の実施完了」の精度を測る。

* 【測定方法】
  * 「影響調査の実施完了」になったにも関わらず、影響調査漏れでWBSを変更したタスクの件数。
  *  作業者より申告。朝会で確認。Notesに記録

| 項目          | 内容                           | 
| ------------- | ------------------------------ | 
| 評価周期      | 週次                           | 
| 評価指標 | 突発的な仕様変更件数           | 
| 目標          | 突発的な仕様変更なし           | 
| 達成度        | 突発的な仕様変更0件／週        | 
| 評価方法      | 突発的な仕様変更件数のカウント |
