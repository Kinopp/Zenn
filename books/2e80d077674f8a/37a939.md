## 🎓 伝説の最終プロジェクト：多次元組織パフォーマンス ＆ 未来予測レポート

あなたは、ある多国籍企業のCEOから、特定のマネージャー（上司）とその配下組織の「収益性・トレンド・コスト予測」を網羅した統合レポートを作成するよう命じられました。

### 【ミッション】

SHスキーマ（売上・製品）とHRスキーマ（従業員・部署）を統合し、以下の5つの高度なロジックを1つのSQL（複数のCTE）で完結させてください。

1. **組織のロールアップ（階層問い合わせ）**:
`EMPLOYEES`テーブルから全組織図を構築し、「各マネージャー自身＋その傘下（部下・孫部下すべて）」のグループを特定してください。
2. **部門売上の紐付け（複雑な結合・集計）**:
各マネージャーの「配下全員」が担当した`SALES`（売上額）を、2021年の月次単位で集計してください。
3. **成長トレンドの検知（MATCH_RECOGNIZE）**:
その組織の月次売上において、「2ヶ月連続で売上が上昇した後に、3ヶ月目にさらに大きく跳ねた（前月比1.2倍以上）」という「ブレイクアウト・パターン」が発生した期間を特定してください。
4. **人件費シミュレーション（MODEL句）**:
現在の組織の総給与コストに基づき、「もし来年、部下全員の給与を3%ずつ、5ヶ月連続で複利的に昇給させた場合」の最終的なコスト推移を算出して下さい。
5. **レポート整形（PIVOT / 分析関数）**:
最終的な出力には、マネージャー名、組織の総売上、トレンドの有無、予測コスト、そして全マネージャー内での「組織効率ランク（売上 ÷ 給与）」を表示してください。

### 🛠️ 挑戦へのヒント

このクエリを組み立てる際は、以下の順序で「CTE（WITH句）」を積み上げていくのがコツです。

* **CTE1**: `CONNECT BY` または再帰 `WITH` で「誰が誰の傘下か」の親子リストを作る。
* **CTE2**: `SALES` を月次集計し、CTE1の階層構造をぶつけて「組織ごとの月次売上」を作る。
* **CTE3**: CTE2に対して `MATCH_RECOGNIZE` をかけ、トレンド行にフラグを立てる。
* **CTE4**: `MODEL` 句を使い、給与データのシミュレーション行を生成する。
* **最終SELECT**: すべてを `JOIN` し、`PIVOT` や分析関数で化粧を施す。

## 🎓 最終卒業検定：模範解答クエリ

```sql
WITH 
-- 1. 組織の全系譜（誰が誰の傘下か）を特定
emp_mapping AS (
    SELECT 
        connect_by_root(e.employee_id) AS manager_id,
        connect_by_root(e.first_name || ' ' || e.last_name) AS manager_name,
        e.employee_id AS sub_id,
        e.salary AS sub_salary
    FROM hr.employees e
    CONNECT BY PRIOR e.employee_id = e.manager_id
),
-- 2. 2021年度の月次売上を集計
monthly_sales AS (
    SELECT 
        cust_id,
        TO_CHAR(time_id, 'YYYYMM') AS tm,
        SUM(amount_sold) AS amount
    FROM sh.sales
    WHERE time_id BETWEEN DATE '2021-01-01' AND DATE '2021-12-31'
    GROUP BY cust_id, TO_CHAR(time_id, 'YYYYMM')
),
-- 3. マネージャーの「傘下組織」としての売上をロールアップ
org_sales_trend AS (
    SELECT 
        m.manager_id,
        m.manager_name,
        s.tm,
        SUM(s.amount) AS org_monthly_amount
    FROM emp_mapping m
    JOIN sh.customers c ON m.sub_id = c.cust_id -- 従業員=顧客と仮定（SH/HR統合用）
    JOIN monthly_sales s ON c.cust_id = s.cust_id
    GROUP BY m.manager_id, m.manager_name, s.tm
),
-- 4. MATCH_RECOGNIZEでブレイクアウト（急成長）を検知
trend_status AS (
    SELECT * FROM org_sales_trend
    MATCH_RECOGNIZE (
        PARTITION BY manager_id, manager_name
        ORDER BY tm
        MEASURES CLASSIFIER() AS pattern_status
        ALL ROWS PER MATCH
        AFTER MATCH SKIP TO NEXT ROW
        PATTERN (UP UP BREAKOUT)
        DEFINE 
            UP AS org_monthly_amount > PREV(org_monthly_amount),
            BREAKOUT AS org_monthly_amount >= PREV(org_monthly_amount) * 1.2
    )
),
-- 5. MODEL句による5ヶ月連続3%複利昇給シミュレーション
salary_forecast AS (
    SELECT 
        manager_id, 
        current_total_sal,
        projected_cost
    FROM (
        SELECT manager_id, SUM(sub_salary) AS current_total_sal
        FROM emp_mapping GROUP BY manager_id
    )
    MODEL 
        PARTITION BY (manager_id)
        DIMENSION BY (0 as month_idx)
        MEASURES (current_total_sal AS projected_cost)
        RULES ITERATE(5) (
            projected_cost[iteration_number + 1] = projected_cost[iteration_number] * 1.03
        )
    WHERE month_idx = 5
)
-- 6. 最終レポートの生成
SELECT 
    t.manager_name,
    TO_CHAR(SUM(t.org_monthly_amount), '99,999,999') AS total_sales_2021,
    MAX(CASE WHEN t.pattern_status = 'BREAKOUT' THEN 'BREAKOUT FOUND!' ELSE 'NONE' END) AS trend,
    TO_CHAR(f.projected_cost, '99,999,999') AS cost_forecast_m5,
    RANK() OVER(ORDER BY SUM(t.org_monthly_amount) / NULLIF(f.current_total_sal, 0) DESC) AS efficiency_rank
FROM trend_status t
JOIN salary_forecast f ON t.manager_id = f.manager_id
GROUP BY t.manager_id, t.manager_name, f.projected_cost, f.current_total_sal
ORDER BY efficiency_rank;

```

## 🛠️ 技術の「合わせ技」解説

このクエリがなぜ「伝説」級なのか。それは、**ビジネスの問いに対して、複数の時間軸と論理軸を同時にぶつけているから**です。

### ❶ 組織の概念を「面」で捉える

`CONNECT_BY_ROOT` を使った `emp_mapping` は、単なる上司部下リストではありません。「この上司の傘下には誰がいるか」という**家系図を全て展開**しています。これにより、組織全体の集計が可能になります。

### ❷ パターンの定義（急成長の瞬間）

`MATCH_RECOGNIZE` 内の `PATTERN (UP UP BREAKOUT)` は、単なる上昇ではなく、「助走（2ヶ月上昇）からの跳躍（1.2倍）」という具体的な商機を特定しています。

### ❸ 数学的な未来予測

給与コストの予測には `MODEL` 句の `ITERATE` を使用しました。
来月のコストは今月の結果に依存する、という複利計算（指数関数的成長）をSQL内で完結させています。


$$\text{Cost}_{n} = \text{Cost}_{0} \times (1.03)^{n}$$

### ❹ 効率の指標化（ROI）

最後の `efficiency_rank` では、以下の計算を行っています。


$$\text{Efficiency} = \frac{\text{Total Organization Sales}}{\text{Current Salary Cost}}$$


「最も少ないコストで、最も多くの売上を稼いでいる組織」はどこか。これこそが経営陣が最も知りたかった答えです。
