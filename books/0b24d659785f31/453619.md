# 【完全版】問題7-16：INTERVAL型を用いた精密な時間の加減算 

### 難易度：★★★★☆ (Lv.4)

## 問題
eコマースおよび物流システム（COスキーマ）において、顧客満足度を維持するために厳しいSLA（サービス品質保証）が設定されています。
注文（`ORDERS`）が確定した瞬間（`ORDER_TMS`）を起点として、システムは以下の2つの重要なデッドラインをリアルタイムに計算し、ダッシュボードに表示する必要があります。

1. **一次検品期限**: 注文確定から **「3時間30分後」**
2. **出荷デッドライン**: 注文確定から **「1日と12時間（36時間）後」**

DATE型のような「1 ＝ 1日」という小数点の計算（`+ 3.5/24` など）は、直感的に分かりにくく計算ミスの原因になります。Oracle SQLが提供する時間間隔専用のデータ型である **`INTERVAL` 型** を駆使して、秒や分、時間単位の精密なスケジュールを算出するクエリを構築してください。

COスキーマ`orders` テーブルからデータを取得し、注文日時（`order_tms`）を基準として以下の2つの日時を計算してください。

* **CHECK_DEADLINE**: 注文日時から **3時間30分後** の日時
* **SHIP_DEADLINE**: 注文日時から **1日と12時間後** の日時

出力にあたっては以下の条件を満たしてください。

1. すべての日付・時刻項目は「YYYY-MM-DD HH24:MI:SS」形式の文字列に変換して表示する。
2. 結果は `order_id` の昇順でソートする。
3. 出力対象は`order_id`が100〜115を対象とする。

## 解答例
```sql:例1：INTERVALリテラルを使用した直感的な記述
SELECT
    order_id,
    TO_CHAR(order_tms, 'YYYY-MM-DD HH24:MI:SS') AS order_tms,
    TO_CHAR(order_tms + INTERVAL '3:30' HOUR TO MINUTE, 'YYYY-MM-DD HH24:MI:SS') AS check_deadline,
    TO_CHAR(order_tms + INTERVAL '1 12' DAY TO HOUR, 'YYYY-MM-DD HH24:MI:SS') AS ship_deadline
FROM
    co.orders
WHERE
    order_id BETWEEN 100 AND 115
ORDER BY
    order_id
```
```sql:例2：NUMTODSINTERVAL関数を使用した動的な記述
SELECT
    order_id,
    TO_CHAR(order_tms, 'YYYY-MM-DD HH24:MI:SS') AS order_tms,
    TO_CHAR(order_tms + NUMTODSINTERVAL(3.5, 'HOUR'), 'YYYY-MM-DD HH24:MI:SS') AS check_deadline,
    TO_CHAR(order_tms + NUMTODSINTERVAL(36, 'HOUR'), 'YYYY-MM-DD HH24:MI:SS') AS ship_deadline
FROM
    co.orders
WHERE
    order_id BETWEEN 100 AND 115
ORDER BY
    order_id
```

## 解説
今回は、時間を「期間（間隔）」として直感的に加減算する **`INTERVAL` 型** のマスターです。
実務、特にECや物流システムでは、今回の「注文から○時間以内」のようなSLA（サービス品質保証）の計算が毎日のように発生します。
かつてDATE型でよく使われていた `+ 3.5 / 24`（3時間半を日単位の小数に変換する計算）は、パッと見て意図が伝わりにくく、バグの温床になりがちでした。
今回は、可読性抜群の「リテラル表記（例1）」と、動的計算に強い「関数表記（例2）」の2つのアプローチが提示されています。それぞれのスマートな仕組みを詳しく解説します。


### 1. スクリプトの解説：時間を時間として足す心地よさ
このクエリの主役は、Oracleが持つ2つの時間間隔データ型（`INTERVAL YEAR TO MONTH` と `INTERVAL DAY TO SECOND`）のうち、細かな時間を扱う **`INTERVAL DAY TO SECOND`** の制御です。

#### 例1：INTERVAL リテラル（固定値の足し算に最強）

英語の文章を読むかのように、直感的に時間を足し算できるのが特徴です。

```sql
order_tms + INTERVAL '3:30' HOUR TO MINUTE
order_tms + INTERVAL '1 12' DAY TO HOUR
```

* **`'3:30' HOUR TO MINUTE`**: 「最高位が時間（HOUR）で、最低位が分（MINUTE）」という意味になり、3時間30分をそのまま表現できます。
* **`'1 12' DAY TO HOUR`**: 「最高位が日（DAY）で、最低位が時間（HOUR）」を表し、1日と12時間をスペース区切りで指定します。

#### 例2：NUMTODSINTERVAL 関数（変数や少数に最強）

「数値（NUMBER）」を「DAY TO SECONDのINTERVAL型」に動的に一発変換する関数です。

```sql
order_tms + NUMTODSINTERVAL(3.5, 'HOUR')
order_tms + NUMTODSINTERVAL(36, 'HOUR')
```

* 3時間30分を「3.5時間」、1日12時間を「36時間」という純粋な **数値** として指定できるため、プログラムから変数を受け取って足し算したい場合に圧倒的に重宝します。

### 2. 文法・テクニックのポイント

#### ① 日付の繰り上がり・サマータイムも完全自動

期待する結果の **`ORDER_ID = 101`** の行に注目してみましょう。

* **注文日時**: `2021-04-03 23:02:19`（深夜の11時すぎ）
* **検品期限**: `2021-04-04 02:32:19`

3時間30分を足したことで、**時間が24時を超えて日付が「4日」に自動で繰り上がっています**。もちろん、月末から翌月への繰り上がり（4月30日 $\rightarrow$ 5月1日）や、うるう年、タイムゾーンを考慮したサマータイムのズレなども、Oracle内部で完全に自動計算されます。

#### ② 2つのアプローチの使い分け

実務では、この2つを以下のように明確に使い分けるのがプロの設計です。

| アプローチ | 構文のイメージ | 実務での主な使いどころ |
| --- | --- | --- |
| **INTERVAL リテラル** (例1) | `INTERVAL '10' MINUTE` | 「30分以内に認証せよ」「1日後にバッチを回せ」など、**仕様として固定されている定数の加減算**。 |
| **NUMTODSINTERVAL** (例2) | `NUMTODSINTERVAL(x, 'DAY')` | 「ユーザーが設定した通知猶予（$X$時間）を足す」など、**画面からの入力値や別テーブルの数値を動的に使いたい時**。 |

> **INTERVAL リテラルの落とし穴**
> リテラル表現（例1）の中に、`INTERVAL :hours HOUR` のようにバインド変数を直接埋め込むことはできません（構文エラーになります）。変数を扱いたいときは、迷わず例2の `NUMTODSINTERVAL` を選択しましょう。

### 3. 実務での活用シーン：SLAと生存期間の制御

この時間の精密なコントロールは、以下のような「期限」がシビアに絡むバックエンド処理で真価を発揮します。

* **チケット・宿泊予約の仮押さえ**: 「予約ボタンを押してから20分間（`INTERVAL '20' MINUTE`）決済がなければ、自動的に在庫を解放する」
* **配送追跡のステータス監視**: 「発送完了から3日（`INTERVAL '3' DAY`）経過しても受取連絡がない場合、ステータスを自動で完了にする」
* **セキュリティ・ワンタイムパスワード**: 「発行から5分30秒（`INTERVAL '5:30' MINUTE TO SECOND`）が過ぎたトークンを無効化する」
