# トポロジ処理および電力システムアプリケーション統合のためのCIM指向データベース

**著者:** Gelli Ravikumar（IEEE学生会員）、Shrikrishna A. Khaparde（IEEEシニア会員）、Yemula Pradeep（IEEE学生会員） IITボンベイ（インド理工学院ボンベイ校）電気工学科 / ワシントン州立大学（WSU）電気工学・コンピュータサイエンス学部 

---

## 概要

電力会社向けソフトウェアアプリケーションをドメインデータ標準である共通情報モデル（CIM）を用いて統合する、標準ベースのシステム統合は存在しています 。しかし、標準指向のデータベース管理システムが不足しているため、多くの電力会社がアプリケーションシステム間でのデータ交換の管理に困難を抱えています 。

標準指向のデータベースは、オブジェクト関係マッピング（ORM）を使用してCIMオブジェクト指向モデルから構築できます 。ORMの汎用的な設計により、オブジェクト指向モデルを任意のデータベーススキーマ・セマンティクスへマッピングすることが可能です 。

本論文では、オブジェクト関係マッピング（ORM）を介したCIM指向データベース（CIMODB）の設計を提案します 。ORMの概念を利用することで、オブジェクト指向パラダイムと関係データベースパラダイムの間でデータを柔軟に移動させることができます 。さらに本論文では、提案するCIMODBと、レガシーなベンダーソフトウェアシステムからのコントロールセンターレベルにおけるトポロジ処理、潮流計算（ロードフロー分析）、およびその他の電力システム研究などの上流電力システムアプリケーションとの統合について探求します 。インドの西部地域の一部であるマハラシュトラ州の400kV・20変電所ネットワークを対象としたケーススタディを示し、CIMODBの概念を詳しく説明します 。

* 
**索引語:** UML、CIM、XML、RDF、データベース、オブジェクト関係マッピング（ORM）、電力システムネットワークモデル

## I. はじめに

既存の電力会社は、電力システムデータの管理および分析のために、広範かつ複雑な情報システムのポートフォリオを保有しています 。異種混合のシステムアーキテクチャはデータ管理の不一致を引き起こしますが、電力会社における様々なシステムの統合には、電力会社統合バス（UIB）や多くのサードパーティ製プラットフォームなどの様々なミドルウェア技術が使用されています 。電力会社のアプリケーション統合のために、正規（カノニカル）データモデルの指定を伴うモデル駆動型統合（MDI）アプローチが記述されています 。ソフトウェアシステムにおけるCIMモデル拡張の管理と、電力会社システムとの統合については過去の文献で記述されています 。

現在、多くの電力会社は、様々なソフトウェアアプリケーションシステムから出力されるデータフォーマットの不一致という問題に直面しています 。そのため、システム間でのデータ交換を管理する取り組みは、異種アプリケーションからの不一致なデータによって損なわれています 。したがって、本論文のテーマとして、オブジェクト関係マッピング（ORM）概念を用いたCIM指向データベース（CIMODB）アプローチを提示します 。CIMODBは、電力会社間および電力会社内でのミドルウェアを介したアプリケーション統合の柔軟性を活用します 。

提案するCIM指向データベースの概念は、企業アプリケーション統合（EAI）、サービス指向アーキテクチャ（SOA）、エンタープライズサービスバス（ESB）、Webサービスなどの主要な技術や標準も活用できます 。このように、本論文は、IEC標準61970および61968で定義されているCIMを電力会社でシームレスに活用することに焦点を当てています 。

CIMは、オブジェクト指向パラダイムにおける統一モデリング言語（UML）で電力システムドメイン全体を定義しています 。電力会社やコントロールセンターにおける既存のデータベースはプロプライエタリ（独自仕様）であり、サードパーティのアプリケーションシステムからのデータアクセスを妨げています 。既存のプロプライエタリなデータベースのために、コントロールセンターのオペレータはサードパーティのアプリケーションシステムと統合する際に困難に直面しています 。このような背景から、電力システム向けのCIMを開始した電力研究所（EPRI）も、CIMに基づくオブジェクト指向データベースの開発に関与してきました 。

これらのシステム間の相互運用性を達成するためには、電力会社がアプリケーションシステムのシームレスな統合に向けてCIMフレームワークの使用へと移行することが不可欠です 。本論文では、電力会社の観点からレガシーソフトウェアシステムの統合にCIM指向データベースをどのように活用できるかを示します 。潮流計算と呼ばれる電力システム研究における伝統的かつ主要なアプリケーションであるトポロジ処理が、CIMODB上に実装されています 。このアプローチにより、データベースレベルでのトポロジ処理のパフォーマンスが向上しました 。

### A. 共通情報モデル（CIM）

共通情報モデル（CIM）は電力システムドメインのモデルであり、世界中の複数のドメインの専門家による2年以上にわたる共同作業によって進化してきました 。CIM/RDF/XMLファイルを介した開始、必要性、意味的理解、静的および動的データ交換、CIMの進化などが報告されています 。これらのCIMの進展により、オブジェクト指向および関係データベースのパラダイムの両方において、柔軟かつ永続的なデータの表現のための魅力的な選択肢となっています 。

## II. オブジェクト関係マッピング（ORM）手法を伴うCIMフレームワーク

### A. オブジェクト関係マッピング（ORM）

オブジェクト関係マッピング（ORM）技術は、オブジェクト指向モデルと関係モデルの間を仲介します 。ORMをマッピングとして適用すると、上位層のクエリはクラスの形式になり、関連する結果をオブジェクトの形式で取得します 。したがって、ORMを伴うアダプタは、関係データベースと、ソフトウェアアプリケーションシステムを含むその他の上位層との間の相互作用を仲介します 。

ORMを使用する利点は次の通りです：

* 
**(i) トランザクション性とデータ整合性:** RDBMSの使用による強化 


* 
**(ii) 再利用性とモジュール性:** オブジェクト指向パラダイムの使用による実現 



### B. CIMフレームワークの記述

CIM指向データベースフレームワークは、プラットフォーム独立モデル（PIM、すなわちUML表現のCIM）と、Python環境で実装されたプラットフォーム固有モデル（PSM、すなわちソフトウェアシステム）を含みます 。

CIMソフトウェアシステムには以下が含まれます ：

* 
**CIM XMIメタスキーマパーサー:** XMI形式のCIMモデルを解析します 。


* 
**CIMモデルジェネレータ:** すべての継承、関連、集約関係を持つクラスオブジェクトとその属性を生成します 。


* 
**ORMマッパー:** クラスオブジェクトのデータベーススキーマを生成します 。


* 
**データベースコネクタ:** データベースへのアダプタとして機能します 。


* 
**CIMODB:** 電力システムデータレコードを保存します 。

## III. ORMを用いたCIM指向データベース設計

### A. 既存のCIMモデルへのORMの適用

CIMモデルにORMを適用する際、以下の3つのマッピングが考慮されます 。

1. CIMモデル全体から関係データベーススキーマへのマッピング 


2. CIMモデル全体からプログラミング言語に応じたソフトウェアクラス定義へのマッピング 


3. クラス定義と関係データベーススキーマの間のマッピング 



CIM成果物とデータベースのマッピングルールは以下の通りです：

* 
**クラスとプロパティ:** テーブルおよびフィールドへの直接的なマッピング 


* 
**データ型:** 関係データベースとプログラミング言語における対応する型へのマッピング 


* 
**継承:** CIMからデータベースへのこの種のマッピングは比較的困難であり、汎化マッピング手法が用いられます 


* 
**関連と集約:** 多対多、一対多、多対一の関係で構成され、主キーと外部キーの概念を使用してマッピングされます 



### B. データベーススキーマ

主キー（Primary Key）と外部キー（Foreign Key）を使用してテーブル間の関連性を強制し、参照整合性（Referential Integrity）を維持します 。図2に示すデータベーススキーマは、特定のCIMプロファイル向けに設計されています 。

### C. データベーススキーマで使用されるテーブルの記述

データベーススキーマは、**静的テーブル、動的テーブル、トポロジテーブル、潮流計算テーブル**で構成されています 。「静的データテーブル」および「動的テーブル」のレコードは、APIを介してCIM/RDF/XMLファイルをインポートすることで取得され、「トポロジテーブル」のレコードはトポロジプロセッサによって取得されます 。

## IV. CIMODBレベルでのトポロジプロセッサ

電力システムネットワークは二通りに表現できます：

* 
**ノード・ブレーカー（Node-Breaker）モデル:** 詳細なスイッチ状態を伴う、ブランチを介したノード接続 。CIMでのネットワークモデル表現に使用されます 。


* 
**バス・ブランチ（Bus-Branch）モデル:** ブランチを介したノード接続のみ 。すべての電力システム研究（潮流計算など）で使用されます 。



そのため、詳細なノード・ブレーカーモデルからバス・ブランチモデルを導出するトポロジ処理が必要です 。トポロジ処理は2つのステップで実行されます ：

1. 
**変電所レベルのトポロジ処理:** スイッチ状態情報を用いてトポロジカルノード（TopologicalNode）を検出します 。


2. 
**ネットワークレベルのトポロジ処理:** ブランチに関連付けられたスイッチ状態を用いてトポロジカルアイランド（TopologicalIsland）を検出します 。



### A. クエリに基づく変電所レベルのトポロジ処理

伝統的なトポロジ処理は `Equipment → Terminal → Connectivity node → Terminal → Equipment` のようにすべてのオブジェクトをクロール（巡回）するため複雑でした 。提案するクエリ指向のアプローチでは、RDBMSの利点を活かして `Equipment → Connectivity node → Equipment` としてクロールするため、計算複雑度が削減され実行パフォーマンスが向上します 。

### C. クエリに基づくネットワークレベルのトポロジ処理

潮流計算アルゴリズムを収束させるには、ネットワークのアイランド（系統分離）情報が必要です 。トポロジ処理は `TopologicalNode → LineSegment → TopologicalNode` のようにオブジェクトをクロールし、トポロジカルアイランドを検出します 。

---

## V. ケーススタディ

目的は、実際の400 kVマハラシュトラ（マハーラーシュトラ）ネットワーク用のCIM/RDF/XMLドメインデータファイルを生成することです 。トポロジカルノードおよびトポロジカルアイランドは、実行中に（オンザフライで）ORMを介してデータベースに保存されます 。また、スケーラブル・ベクター・グラフィックス（SVG）に基づく可視化も実装され、アイランドが異なる色で描写されます 。

* 
**使用環境:** MySQL (XAMPPサーバー)、4GBメモリ、Linux OS 


* 
**ファイルサイズ:** 1672 KB 


* 
**フルファイルのインポート時間:** 2.48秒 



### トポロジプロセッサの処理時間比較

| 構成 | 総経過時間 |
| --- | --- |
| **CIMODBあり (提案手法)** | **0.112 秒** |
| CIMODBなし (従来手法) | 1.492 秒  |

提案手法（CIMODBあり）によって、トポロジ処理の実行パフォーマンスが大幅に向上していることがわかります 。

---

## VI. 結論

本論文では、ORMを介した関係データベース（RDBMS）を用いた電力システムアプリケーションのためのCIMフレームワークのモデリングと実装について説明しました 。実用的なケーススタディにより、提案するCIMODBがトポロジ処理において優れた実行パフォーマンスを示すことが実証されました 。このCIMODBは、ベンダーの観点からは実装の容易性において、また電力会社の観点からは中心的なデータベースアクセスとして非常に有利であると考えられます 。
